# Voice Arena — Speaker Diarization Evaluation Pilot

This repository contains a Google Colab experiment supporting my Voice Arena FDE take-home assessment. The pilot compares two speaker diarization pipelines on the same recordings using human-annotated reference speaker turns.

**Notebook:** [Open in Google Colab](https://colab.research.google.com/drive/1mHrRsjwYuVNTZy-O8nyflIiCM8YZmrCl?usp=sharing)

## What I evaluated

| Component | Configuration |
| --- | --- |
| Models | `pyannote/speaker-diarization-3.1`, `pyannote/speaker-diarization-community-1` |
| Input | WAV recordings paired with reference RTTM annotations |
| Primary metric | Diarization Error Rate (DER; lower is better) |
| Additional metrics | Jaccard Error Rate (JER), absolute speaker-count error, inference time |
| Collar | 0 seconds |
| Overlap | Included (`skip_overlap=False`) |
| Speaker count | Not supplied to either model |
| Scoring region | Entire recording in the notebook (no UEM file) |

The saved pilot results contain **five recordings and ten model runs**. The notebook template initially validates 2–3 recording pairs, following the assessment's optional-experiment suggestion. **To rerun all five pilot clips, change the manifest validation from `2 <= len(manifest) <= 3` to `2 <= len(manifest) <= 5`.** This does not change the scoring logic.

## Results

The exported `results.json` reports these **unweighted means of per-recording values** (not corpus-level DER/JER):

| Model | Mean clip DER | Mean clip JER | Mean inference time |
| --- | ---: | ---: | ---: |
| pyannote 3.1 | 68.65% | 85.32% | 16.04 s |
| Community-1 | 56.18% | 71.66% | 17.46 s |

Community-1 had lower DER on each of the five clips in this pilot. These descriptive results are not a statistically powered claim that one model is generally superior. In particular, the pilot's reference speaker counts and predicted counts warrant closer inspection. See the assessment document for interpretation.

## Run in Google Colab

1. Open the linked notebook, or upload `Voice_Arena_Diarization_Colab.ipynb` to [Google Colab](https://colab.research.google.com/).
2. Select a GPU runtime if available.
3. Visit the Hugging Face model pages and accept their terms if prompted:
   - https://huggingface.co/pyannote/speaker-diarization-3.1
   - https://huggingface.co/pyannote/speaker-diarization-community-1
4. Add a Hugging Face **read token** to Colab Secrets under `HF_TOKEN`. Do not put tokens in notebook cells or commit them.
5. Upload a ZIP with matching WAV/RTTM filenames, for example:

   ```text
   pilot_data/
     clip_01.wav
     clip_01.rttm
     clip_02.wav
     clip_02.rttm
   ```

6. Run the cells in order. The notebook loads both pipelines, produces RTTM predictions, scores each recording, plots DER by clip, and downloads a ZIP containing `results.csv`, `results.json`, and prediction RTTMs.

Use recordings and reference annotations you have permission to process. Public resources to explore include [AMI](https://groups.inf.ed.ac.uk/ami/corpus/) and [VoxConverse](https://github.com/joonson/voxconverse). Verify that any audio excerpt and RTTM timestamps align; trimmed clips require correspondingly adjusted reference timestamps.

## Dependencies and environment

The notebook installs its own packages in Colab. For a local environment, start with:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
```

The notebook itself uses Colab-specific file-upload and secret APIs, so local execution requires replacing those cells. The saved experiment metadata records **CUDA**, `pyannote.audio==4.0.7`, and `pyannote.metrics==4.2.0`. `requirements.txt` uses compatible minimums rather than claiming a fully frozen, platform-independent environment; PyTorch/CUDA availability depends on the runtime.

## Reproducibility and interpretation

- `results.json` records package versions, device, scoring settings, audio/reference SHA-256 hashes, model names, and per-clip metrics.
- Prediction RTTM files are the speaker-turn outputs generated by the models.
- The reference audio and annotations are **not** included in the exported results ZIP. Reproduction requires the same source files, confirmed using their hashes.
- The notebook computes DER and JER per clip. Its descriptive mean is not a duration-weighted corpus DER; for a full benchmark, sum error components over all clips and divide by total reference speaker-time.
- No speaker count is provided to either model. Overlapping speech is included in the score.
- Five clips are enough to exercise the pipeline and inspect failure modes, not to establish general model rankings or meaningful confidence intervals.
